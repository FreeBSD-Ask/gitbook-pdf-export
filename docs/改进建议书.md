# gitbook-pdf-export 全方位改进建议书

> 生成日期：2026-11-20
> 版本基线：mdconv.py（本轮改造后）、WeasyPrint 70、mistune 3.4、EbookLib 0.21、python-docx 1.2、Python 3.15
> 研究范围：中国国家标准（GB）、国际标准（ISO/IEC、W3C）、行业规范（出版/印刷）、开源社区实践、供应链安全

---

## 一、现状评估摘要

本项目已实现：GitBook 式 Markdown → PDF（PDF/A-4，基于 PDF 2.0）+ EPUB 3 + Word（OOXML）三格式导出，霞鹜文楷 GB 版屏幕阅读版全量嵌入，BSD 命令自定义高亮，PDF 侧边栏书签（章/节/小节三级），EPUB 两级目录与跨章链接重映射，多平台 CI 矩阵。

本建议书按「标准符合度 → 可访问性 → 出版行业规范 → 安全与供应链 → 工程与自动化」五个维度，给出分级（P0 必做 / P1 应做 / P2 建议）落地路线。

## 三、字体与排版（本轮已实现 + 建议）

### 已实现
- 正文与代码全量嵌入霞鹜文楷 **GB 版**屏幕阅读版（国标字形，SIL OFL 1.1，允许自由嵌入分发；授权文本应随产物分发，见 §六 P1）
- 行距 1.9、两端对齐、孤行寡行控制（orphans/widows: 3）、首行缩进 2 字符
- PDF 侧边栏书签按 Markdown 标题级别生成（`--bookmark-depth` 控制深度，默认到二级标题），并在正文前生成带页码的目录页（页码由 `target-counter` 计算，封面与目录不计入页序）；源目录文件（mu-lu.md）不再排版成页
- 注释统一取消斜体（中文斜体不符合印刷规范）

### 建议
- **P1 字重系统**：引入霞鹜文楷 Medium（屏幕版同仓库提供多字重时）作为标题字重，避免伪加粗（synthetic bold）导致的笔画糊化；EPUB 需同步嵌入
- **P1 标点悬挂与避头尾**：CSS `line-break: strict`（WeasyPrint 支持）保证行首行尾标点规则符合 GB/T 15834 的阅读习惯
- **P1 页眉**：`@page @top-center content: string(chapter-title)`，配合 `h1 { string-set: chapter-title content() }`，实现「页眉显示章名」的书籍惯例（封面页可用命名页单独隐藏页码）
- **P1 装订线**：双面打印场景使用 `@page :left / :right` 分设内外边距（外侧 2cm、内侧 2.5cm 预留装订边）
- **P2 封面页规范**：封面单独一页不含页眉页脚已实现；建议封面下增加「半标题页（书名 + 社区名）+ 版权页」（见 §五）
- **P2 行内代码与正文的字号级差**已设 0.92em；长 URL 建议加 `overflow-wrap: anywhere` 防溢出

## 四、可访问性（EPUB Accessibility 1.1 / WCAG 2.2 / PDF/UA）

| 项目 | 等级 | 做法 |
|---|---|---|
| 图片替代文本 | P0 | 构建时扫描无 `alt` 的 `<img>`，输出告警清单（CI 可设阈值）；公式 SVG 已有 alt="formula"，建议升级为公式的纯文本描述（取 LaTeX 源的 text 化） |
| 语义标注 | P1 | EPUB 章节文件加 `epub:type="chapter/section"`；脚注加 `epub:type="footnote"`（mistune footnotes 插件输出后补标注） |
| 阅读顺序与结构 | P1 | PDF 侧启用 WeasyPrint tagged PDF（`pdf_variant="pdf/ua-1"` 或后续 UA-2 支持），保证屏幕阅读器可按标题/表格导航 |
| EPUBCheck 门禁 | P0 | CI 中运行 EPUBCheck（`w3c/epubcheck` releases jar），零 error 才允许发布 |
| 链接可达性 | P1 | 产物内链跳转已在 PDF/EPUB 验证（764 个 GoTo 链接）；建议 CI 中用 PyMuPDF 断言「内部链接数 > 0 且目标存在」防回归 |
| 语言标签 | P0 | `zh-CN` → `zh-Hans`（含 EPUB dc:language 与 HTML lang） |

## 五、出版行业规范（书籍结构完整性）

正式出版物正文前应包含（CY/T 惯例与主流技术书籍实践）：

1. **半标题页**：仅书名（P1）
2. **版权页**：书名、版本与构建信息（git commit hash + 构建日期，P0——可追溯性）、许可证（源文档许可 + 字体许可 + 工具许可三层声明）、联系人（P1）
3. **扉页**：书名 + 副书名 + 编著者（P2）
4. **目录**：已有（PDF 目录页与书签 / EPUB nav / Word 域）；目录页与封面不计入页码，正文从第 1 页开始，未采用罗马数字前序（如需与印刷惯例完全对齐可再叠加）
5. **版本与修订记录页**：映射源仓库 CHANGELOG（P2）

实现路径：`main()` 在 cover 之后注入由元数据（CLI/元文件）渲染的 front-matter HTML 块，全部用 CSS `page-break-after` 控制。

## 六、安全与供应链

| 项目 | 等级 | 做法 |
|---|---|---|
| CI 最小权限 | P0（已做） | workflows 顶层 `permissions: contents: read` |
| 依赖哈希锁定 | P1 | `pip install --require-hashes` + requirements 锁文件（pip-compile --generate-hashes），防 PyPI 投毒 |
| SBOM | P1 | CI 生成 CycloneDX SBOM（`cyclonedx-bom`）随 release 附带 |
| 二进制校验和与签名 | P1 | release 附 SHA-256SUMS 并用 cosign/minisign 签名；PyInstaller onefile 建议改 onedir + 打包校验（onefile 解压到临时目录存在 TOCTOU 面） |
| 多进程隔离 | P2 | 公式渲染调用外部 xelatex/dvisvgm：文档仓库不可信时（CI 拉取任意 GitBook 源）应限制公式源码长度/字符集白名单，防 LaTeX 命令注入（\write18 shell-escape 已禁用，但 \input{file} 可读文件）——建议 preprocess 阶段过滤 `\write`、`\input`、`\openout` 等危险命令 |
| 远程图片抓取 | P1 | 已有 UA 头；建议加 Content-Type 白名单（image/*）、响应大小上限（如 20MB）、私网地址拒绝（防 SSRF 打内网元数据端点） |
| HTML 清洗 | P2 | `escape=False` 透传原始 HTML 是 GitBook 场景的合理选择；对外发布工具应提供 `--sanitize` 选项（allowlist 标签） |

## 七、工程与自动化

- **P0 验证管线**：`python -m unittest`（已有 14 用例）+ PyMuPDF 内链断言 + veraPDF（PDF/A-4，`tests/verapdf_cli.py`，已入 `.github/workflows/tests.yml`）；EPUBCheck 尚缺
- **P1 发布自动化**：tag 触发 release workflow，产出三格式 + SBOM + 校验和
- **P1 性能**：公式持久缓存已实现；进一步可将 PDF 渲染并行化（WeasyPrint 单线程，可按章分片渲染后 pydyf 合并——收益大但改动大，列为 P2 备选）
- **P2 字体子集化**：提供 `--subset-fonts` 选项（pyftsubset 预处理），对正式发布可把 2×26MB 字体裁剪到数 MB；「全量嵌入」保持为默认
- **P2 兼容性矩阵**：CI 已覆盖 Ubuntu 26.04 x64/arm64、Windows x64/arm64、macOS arm64、FreeBSD 14.3、OpenBSD、NetBSD；建议补 macOS Intel（macos-15-intel 尚在支持期）按需添加
- **P2 文档 lint**：建议书层面推荐 FreeBSD-Ask 源仓库引入 markdownlint + Vale + lychee（链接检查），与本工具 CI 互补
